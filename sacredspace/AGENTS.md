# SacredSpace app

## Overview

A progressive web app for reading and listening to Sanskrit mantras and stotras: a public deity directory and mantra reader with likes, saved collections, search, and audio, plus a Clerk-gated admin panel for content, audio, and analytics.

## Key files

| File | Owns |
|---|---|
| `src/routes/` | File-based routes; `routeTree.gen.ts` is auto-generated, never edit it |
| `src/routes/__root.tsx` | Root layout: ClerkProvider → QueryClient → Audio → Toast providers, theme script |
| `src/server/db/schema.ts` | Drizzle schema: `deities`, `contents`, `likes` (unique `content_id`+`session_id`) |
| `src/server/db/index.ts` | Cold-start bootstrap: env validation, client, WAL, `ensureSeeded()` migrations |
| `src/server/functions/*.ts` | All backend logic as TanStack Start server functions |
| `src/server/functions/validators.ts` | Centralized Zod schemas for every server function input |
| `src/lib/errors.ts` | Typed `AppError` classes (401/404/409/429) |
| `src/lib/rate-limit.ts` | Limiter with Upstash Redis or in-memory backends (fail-open) |
| `src/lib/storage.ts` | Uploads: Vercel Blob in prod, local disk in dev; orphan Blob cleanup |
| `src/components/` | Shared UI (skeletons, toasts, modals, ProseRenderer) |

## Commands

All commands run inside `sacredspace/`. Dev, build, test as at root. Additional:

```bash
npm run db:generate    # Drizzle migration files
npm run db:push        # Apply schema to the DB
npm run db:studio      # Drizzle Studio
npm run db:seed        # Manual seed (also auto-seeds on boot)
```

## Conventions

- Server functions follow four patterns: public read (rate-limited, unauthenticated), admin write (Clerk-gated + role check + rate-limited), typed errors, Zod validators from `validators.ts`.
- Slug changes/enforcement: uniqueness pre-checked with `ConflictError` (409), never surfaced raw DB errors.
- Public queries filter `status = 'published'`; drafts are admin-only everywhere, including mantras-of-the-day picks.
- Likes dedupe on `(content_id, session_id)`; anonymous identity: likes via httpOnly cookie session, saved collection via localStorage.
- The limiter is async; always `await` `checkRateLimit`/`enforceRateLimit`.
- Route loaders fetch; components render `pendingComponent`/`errorComponent` states. Every screen ships empty, loading, and error states.
- Tailwind v4 with Material-3-inspired tokens; dark mode via `useTheme()` hook (no-flash script in `__root.tsx` head).
- HTML content is sanitized on the server (`sanitize-html`) and client (DOMPurify).
- Seed images in `public/uploads/` are git-committed; Blob-only cleanup deletes replaced uploads, never seed files.

## Gotchas

- On Vercel without Turso env vars, the DB is ephemeral `/tmp` SQLite: every cold start reseeds. Set `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN` for persistence.
- Schema changes must be added to the incremental migrations in `src/server/db/index.ts`, not only pushed locally, or prod cold starts won't have them.
- `getClientIp()` falls back to `"anonymous"` outside request contexts (tests); rate-limit counters are per-process without Upstash.
- Never edit `src/routeTree.gen.ts`; it is regenerated by the router plugin.
- Playwright e2e (`e2e/auth.spec.ts`) runs against the dev server; see `playwright.config.ts` for the base URL.
